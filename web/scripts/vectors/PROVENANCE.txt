WHY VENDORED, WHEN THE SCRIPT USED TO FETCH
    check_mlkem_modulus_vectors.mjs fetched these at run time so it would always test the
    CURRENT published set. That is a real benefit and it is preserved: pass --live to fetch
    instead of reading these files. But it also meant the check could not gate CI - CI is
    offline by design, and the alternative would have been a network-failure fallback. This
    check is one skip-on-error away from being a conformance script that always passes, which
    is worse than having none: it found @noble/post-quantum 0.2.1 accepting all 2,595
    malformed encapsulation keys, and a version of it that quietly skips would have reported
    that build clean. So the snapshot is the default and the network is the option, not the
    reverse.

WHAT TO DO IF --live DISAGREES WITH THIS SNAPSHOT
    Upstream added or corrected vectors. That is information, not a failure: re-fetch at the
    new sha, update this file, and re-run. The sha above is what makes "disagrees" a question
    with an answer rather than a mystery.
